Plugin Overview

ASuperTAB is a server-interface plugin built to centralize the parts players see constantly: the TAB list, sidebar scoreboard, player rank formatting, custom tags, ping displays, animated text, and floating information above/below players.

TAB List

Custom names, header/footer, native ping and configurable refresh.

Automatic Sorting

LuckPerms weight sorting without forcing your visual TAB format.

Scoreboards

Separate Java and Bedrock layouts with optional hidden score numbers.

RGB & Animations

Legacy colors, HEX colors, gradients, rainbow, pulse, typewriter and frame animations.

Custom Tags

Unlockable/selectable tags with requirement checks and a GUI.

User Lines

Extra placeholder-driven floating text above and below players.

Design principle: sorting and appearance are separate. Enabling automatic LuckPerms sorting does not require you to use grouptab.yml formatting.

Installation

  1. Stop the server completely.
  2. Install ACore in the plugins folder.
  3. Place ASuperTAB-v1.0.0.jar in the same folder.
  4. Install any optional integrations you want, such as PlaceholderAPI and LuckPerms.
  5. Start the server once so ASuperTAB can create its YAML files.
  6. Edit the generated files inside plugins/ASuperTAB/.
  7. For normal config edits use /asupertab reload. For JAR/dependency changes, do a full restart.
plugins/
├── ACore.jar
├── ASuperTAB-v1.0.0.jar
├── PlaceholderAPI.jar      # optional
└── LuckPerms.jar           # optional

Dependencies & Supported Integrations

Required: ACore

ACore is a hard dependency. Bukkit/Paper loads ACore before ASuperTAB. If ACore is missing or fails to enable, ASuperTAB will not start.

config.yml

This is ASuperTAB's main control file.

Refresh rate

updates:
  tab-refresh-ticks: 20

20 ticks is approximately one second on a server running at 20 TPS. Lower values refresh more often; higher values refresh less often.

Unresolved placeholders

placeholders:
  unresolved-mode: KEEP

KEEP leaves the placeholder visible, EMPTY hides it, and UNKNOWN replaces it with ?.

TAB name format

tablist:
  enabled: true
  name:
    use-group-format: false
    format: "%player_name%"

Set use-group-format: false when you want one universal format, such as:

format: "%luckperms_prefix%%player_name% &7%asupertab_tags%"

Set it to true when you want prefixes/names/suffixes to come from each LuckPerms group in grouptab.yml.

Native TAB ping

tablist:
  ping:
    enabled: true

Automatic LuckPerms sorting

tablist:
  auto-sort:
    enabled: true
    higher-weight-first: true
    same-weight-sort: ALPHABETICAL

When enabled, ASuperTAB sorts players by LuckPerms weight. Players with equal weight are sorted alphabetically. This sorting is independent from visual group formatting.

Java header & footer

tablist:
  java:
    header:

scoreboard.yml

Controls the right-side sidebar independently for Java and Bedrock.

grouptab.yml

Use this file when you want different TAB/nametag designs for different LuckPerms groups.

groups:
  admin:
    priority: 10
    tab:
      prefix: "&c&lADMIN &c"
      name: "%player_name%"
      suffix: " %asupertab_tags%"
    nametag:
      prefix: "&c&lADMIN &c"
      name: "%player_name%"
      suffix: ""

The group key (for example admin) should match the LuckPerms group name. Add as many groups as needed.

To actually use these group-specific TAB designs, set tablist.name.use-group-format: true in config.yml. Leave it false if you prefer a single PlaceholderAPI/LuckPerms-based format.

astags.yml

The optional Tags module lets players unlock and select custom tags through /astags.

enabled: true
settings:
  allow-no-tag: true
  only-one-active-tag: true

gui:
  title: "&8ASuperTAB Tags"
  rows: 6

Create a tag

ASuperTABtags:
  hunter:
    name: "Hunter"
    tagshow: "&c[Hunter]"
    requirements:
      - "%statistic_player_kills% >= 3"
    gui:
      material: IRON_SWORD
      slot: 10
      name: "&cHunter"
      lore:
        - "&7Requirement:"
        - "&fKill at least 3 players"

hunter is the internal ID. tagshow is the text displayed by %asupertab_tags%. Requirements are evaluated from placeholder values, so PlaceholderAPI and the appropriate expansions/plugins must provide those placeholders.

More requirement examples

# Economy
- "%vault_eco_balance% >= 1000000"

# Playtime
- "%statistic_hours_played% >= 100"

animation.yml

Create reusable animated values and place them anywhere ASuperTAB parses placeholders with:

%asupertab_animation_<animation-id>%

Supported types: FRAMES, RAINBOW, GRADIENT, TYPEWRITER, PULSE.

RAINBOW

animations:
  rainbow-title:
    enabled: true
    type: RAINBOW
    text: "ASuperTAB"
    interval-ticks: 2
    colors:
      - "#FF0000"
      - "#FFFF00"
      - "#00FF00"
      - "#00FFFF"
      - "#5555FF"
      - "#AA00FF"

GRADIENT

server-gradient:
  enabled: true
  type: GRADIENT
  text: "YourServer"
  interval-ticks: 3
  colors:
    - "#00FFFF"
    - "#AA55FF"
    - "#FF55AA"

TYPEWRITER

welcome-typewriter:
  enabled: true
  type: TYPEWRITER
  text: "Welcome to the server!"
  interval-ticks: 2
  pause-ticks: 30

PULSE

pulse:
  enabled: true
  type: PULSE
  text: "PLAY NOW"
  interval-ticks: 5
  colors:
    - "#FFFFFF"
    - "#55FFFF"
    - "#AA55FF"

FRAMES

custom-frames:
  enabled: true
  type: FRAMES
  interval-ticks: 10
  frames:
    - "&fWelcome!"
    - "7FFFFHave fun!"
    - "<gradient:#55FFFF:#AA55FF>ASuperTAB</gradient>"

userlines.yml

Controls extra floating information above and below each player's normal name.

enabled: true
settings:
  update-interval-ticks: 5
  view-range: 32.0
  hide-own-lines: true
  base-height: 0.90
  passenger-anchor-offset: 0.0
  distance-between-lines: 0.28
  show-player-name: true
  player-name-format: "&f%player_name%"

What the settings mean

SettingPurpose
update-interval-ticksHow often placeholder text refreshes.
view-rangeApproximate distance at which floating lines are shown.
hide-own-linesPrevents a player from seeing their own extra lines.
base-heightMoves the full line stack up/down.
distance-between-linesVertical spacing between lines.
show-player-nameShows the player's name in the center of the stack.

Java lines

java:
  enabled: true
  above:
    line-2:
      enabled: true
      text: "&6Level &f%player_level%"
    line-1:
      enabled: true
      text: "%asupertab_tags%"
  below:
    line-1:
      enabled: true
      text: "&c❤ &f%asupertab_health%"
    line-2:
      enabled: true

Bedrock lines

Bedrock floating lines are disabled by default because Geyser/Bedrock rendering can differ. Test before enabling.

Frequently Asked Questions

Why won't ASuperTAB start?

Check that ACore is installed and successfully enabled. ACore is a hard dependency.

Do I need PlaceholderAPI?

No, but it is strongly recommended if you want placeholders from LuckPerms, Vault, statistics, or other plugins.

Why did my TAB names become plain?

Use tablist.name.use-group-format: false if you want ASuperTAB to preserve one universal placeholder-driven format. Automatic sorting can remain enabled separately.

How do I make grouptab.yml actually control names?

Set tablist.name.use-group-format: true in config.yml and make sure the group names match your LuckPerms groups.

How do I hide the red 1–9 numbers on the scoreboard?

Keep settings.hide-score-numbers: true in scoreboard.yml.

Can players disable only their own scoreboard?

Yes. /asbtoggle hides/shows only that player's sidebar for the current session.

Does /asbtoggle disable the TAB list too?

No. TAB, sorting, tags, ping and animations remain active.

Can Java and Bedrock have different layouts?

Yes. scoreboard.yml has separate Java and Bedrock sections, and userlines.yml also provides platform-specific sections.

Can I create custom tags?

Yes. Add them under ASuperTABtags in astags.yml and configure the visible text, requirement(s), material, slot, name and lore.

Can I animate text?

Yes. Define an animation in animation.yml, then use %asupertab_animation_<id>% where ASuperTAB parses placeholders.

Should I reload or restart?

Use /asupertab reload for normal configuration changes. Fully restart when replacing JARs, adding dependencies, or troubleshooting startup issues.
